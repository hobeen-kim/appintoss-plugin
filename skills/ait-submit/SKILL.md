# 앱인토스 제출 가이드

제출 전 최종 검수를 실행하고, Developer Center 콘솔에 입력할 출시 노트와 기능 목록을 `docs/SUBMIT.md`에 정리한다.

## SUBMIT.md 집약 규칙 (단일 파일 원칙)

**콘솔 업로드 관련 정보는 모두 SUBMIT.md 한 파일에 집약한다. 업로드·제출·검수 관련 신규 산출물이 생기면 별도 파일이 아니라 SUBMIT.md에 섹션으로 추가한다.**

SUBMIT.md 필수 포함 항목 — 6개 그룹:

1. **앱 기본 정보**: 앱명(콘솔 등록정보와 일치 — 불일치는 반려 사유), 카테고리 추천 1순위 + 대안 1, 상세설명·출시노트
2. **에셋**: 아이콘 600×600 · 화면예시 636×1048 ×3 · 썸네일 1932×828 절대경로
3. **토스 로그인 콘솔 설정**: 동의항목표·콜백·약관 URL (로그인 사용 앱만)
4. **업로드 절차**: `.ait` 경로·버전, `ait deploy -m "출시메모"` 옵션(SDK 2.3.0), 앱 정보 등록 간소화(2026-05-11 콘솔 변경 — 등록 시 최소 정보만 입력) 반영
5. **검수 안내**: 검수 4단계(운영/디자인/기능/보안)·영업일 2~3일, 재검수는 수 시간 내, **앱 정보 검수와 코드 검수는 별개 단계**, 자동 검수 오탐 시 채널톡 수동 승인 경로
6. **검수 전 자가점검 요약**: REVIEW-REPORT(검수 체크리스트 결과) 링크

## 실행 순서

### 1단계: ait-review 검수 실행

`ait-review` 스킬의 11단계 체크리스트를 실행한다. 하나라도 실패하면 제출을 중단하고 수정 사항을 안내한다.

### 2단계: docs/SUBMIT.md 읽기 또는 생성

프로젝트의 `docs/SUBMIT.md`를 읽는다. 파일이 없으면 `references/submit-template.md` 템플릿으로 새로 생성한다.

### 3단계: SUBMIT.md 업데이트

아래 정보를 코드베이스에서 자동으로 수집하여 채운다:

#### 스토어 노출 정보 (부제·상세 설명·카테고리·키워드)
- **부제**: 서비스 성격이 한눈에 이해되게 간결히. **느낌표(!)·비속어 금지**, 과장 금지. 작성 규칙은 `references/submit-store-guide.md` 참조
- **상세 설명**: 사용자 관점 — 경험할 수 있는 내용을 구체적으로(핵심 기능·시나리오·차별점). 카피 보이스 일관. **"~없습니다/안 됩니다" 부정 나열·방어적 프라이버시 고지 금지**(출시 노트 톤 규칙과 동일). 금지: 과장, 금융상품 추천성 문구, 외부 서비스·앱 설치 유도. 규칙: `references/submit-store-guide.md`
- **카테고리**: `references/categories.md`의 **선택 가능 항목만** 사용. PLAN.md 주제·타겟 기반 **2개 추천**(1순위 + 대안), 소분류 있으면 '대분류 · 소분류'로. 금융 그룹은 선택 불가
- **검색 키워드**: 타겟 사용자가 검색할 단어 10개

#### 출시 노트 (create — 최초 1회)
- Developer Center 콘솔의 **"빠른 검토를 위해, 앱의 주요 화면과 기능을 간단히 소개해주세요."** 항목에 입력할 내용
- 코드베이스(라우터, 페이지 컴포넌트)를 분석하여 앱의 주요 화면과 기능을 소개하는 글 작성
- 변경사항 나열이 아니라 **앱 전체를 처음 보는 검수자에게 앱을 소개**하는 방식으로 작성
- 한국어로, 3~6줄 이내
- create·update 무관하게 "출시 노트" 섹션은 최초 작성본을 유지(앱 소개는 변하지 않으면 그대로)

**톤 규칙 (중요 — 자연스럽게)**:
- **"~하지 않습니다 / ~없습니다 / ~안 됩니다" 부정·방어 문구를 나열하지 마라.** 정책 준수(금융상품 추천 없음·외부 송금 없음·앱 설치 유도 없음 등)는 코드와 검수가 보장하므로, 출시 노트에 변명처럼 적지 않는다.
- **프라이버시·저장 방식을 강박적으로 반복하지 마라.** "기기에만 저장/서버 미전송"은 그것이 앱의 **핵심 차별점일 때만 1회**, 사용자 가치 표현으로(예: "기록은 내 폰에만 안전하게 남아요") — 검수 회피용 고지처럼 쓰지 않는다.
- 무엇을 **해주는지**(사용자 가치·핵심 사용 흐름) 중심으로, 사람이 앱스토어 소개글 읽듯 자연스럽게. 기능 메커니즘(가중 합산·데이터 건수 등)은 1줄로 충분.
- 좋은 예 결: "결혼식·장례·돌잔치에서 얼마를 내야 할지 고민될 때, 관계와 상황을 고르면 적정 금액을 알려드려요. 낸 금액은 따로 기록해 다음에 참고할 수 있어요."

#### 업데이트 노트 (update — 버전별 누적)
- **create·update 모두** SUBMIT.md에 "업데이트 노트" 섹션을 유지한다.
- update 실행마다 **최신 버전 항목을 맨 위에 추가**한다(`### v{버전} ({일시})` + 변경 1~3줄). **기존 버전 노트는 삭제하지 않고 아래에 누적 보존.**
- 사용자 관점으로 이번 버전에서 달라진 점만. 과장·금지표현 불가.
- create 최초 생성 시에는 `### v{초기버전} (최초 출시)` 한 줄로 시작.
- 이 내용은 update 보고서(REPORT) §3-1 업데이트 노트와 동일하게 맞춘다.

#### 제출 에셋 임베드
- `docs/assets/`의 아이콘(icon.png 600×600)·화면예시 3장(screenshot-1~3.png 636×1048)·썸네일/배너(thumbnail.png 1932×828)를 SUBMIT.md "제출 에셋" 표에 **상대경로 + 미리보기 임베드**(`![](assets/파일명)`)로 기록한다.
- 에셋 파일이 없으면 해당 행에 "미생성" 표기(조용한 누락 금지). 규격은 sips 실측값을 함께 적는다.

#### 토스 로그인 설정 (로그인 사용 앱만)
- 로그인을 쓰는 앱은 SUBMIT.md에 "토스 로그인 설정" 섹션을 추가한다. `ait-login/references/oauth-consent-guide.md` 기준.
- **동의 항목 추천표**(항목·scope·필수/선택/사용안함·근거) + **콜백 필수 여부 자동 판정**(이름·이메일·성별 외 항목 켜면 필수) + **약관 URL**(서비스 이용약관 필수·개인정보 처리방침, `docs/legal/` 생성 후 서버 정적 라우트 URL 또는 '호스팅 필요' 상태).
- 로그인 미사용 앱은 이 섹션 생략.

#### 앱 내 기능 목록
- 라우터 설정(react-router-dom)에서 페이지 경로를 추출
- 각 페이지의 실제 역할을 코드에서 파악
- **최소 1개, 최대 3개**만 작성 (핵심 기능 위주로 선별)
- 딥링크 URL 형식: `intoss://{appName}/{path}`
  - `appName`은 `granite.config.ts`에서 읽음
  - `path`는 라우터 경로 (예: `/`, `/result`, `/calc/loan`)

| 한국어 기능 이름 | 영어 기능 이름 | 딥링크 |
|----------------|---------------|--------|
| 홈 | Home | intoss://{appName}/ |
| ... | ... | ... |

#### 콘솔 대조 항목
- `granite.config.ts`에서 appName, displayName, icon 추출
- `ait-build-output.md` 포맷과 동일하게 출력
- 앱명은 콘솔 등록정보와 일치해야 한다 — **불일치는 반려 사유**

#### 업로드 절차
- 빌드된 `.ait` 파일의 경로와 버전을 기록한다.
- `ait deploy -m "출시메모"` 옵션(SDK 2.3.0)으로 출시 메모를 함께 전달할 수 있음을 안내한다.
- 앱 정보 등록 간소화(2026-05-11 콘솔 변경 — 등록 시 최소 정보만 입력) 기준으로 절차를 작성한다.

#### 검수 안내
- 검수는 4단계(운영/디자인/기능/보안)로 진행되며 영업일 기준 2~3일 소요, 재검수는 수 시간 내 완료된다.
- **앱 정보 검수와 코드 검수는 별개 단계**임을 명시한다.
- 자동 검수 오탐 시 채널톡으로 수동 승인을 요청하는 경로를 안내한다.

#### 검수 전 자가점검 요약
- REVIEW-REPORT(검수 체크리스트 결과) 링크를 기록한다.

### 4단계: SUBMIT.md 출력

완성된 SUBMIT.md 전문을 출력한다. 사용자가 Developer Center 콘솔에 바로 복사해서 쓸 수 있도록 한다.
