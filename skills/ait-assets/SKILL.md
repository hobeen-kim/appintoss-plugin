# 앱인토스 콘솔 제출 에셋 생성 가이드

앱인토스 콘솔에 미니앱을 제출할 때 필요한 스토어 에셋(앱 아이콘, 앱 화면 예시, 앱 썸네일)을 headless 브라우저 렌더로 자동 생성한다. 모든 에셋은 콘솔이 요구하는 정확한 픽셀 규격을 만족해야 하며, 생성 후 실측 검증을 거친다.

## 1. 에셋 규격 표 (확정 수치, 임의 변경 금지)

| 에셋 | 규격 | 수량 | 대상 | 생성 방식 |
|------|------|------|------|-----------|
| 앱 로고(아이콘) | 600×600 PNG **정사각·모서리 각짐·배경색 필수** | 1장 | 전체 (필수) | SVG/HTML 템플릿 디자인 → headless 브라우저 렌더 |
| 앱 화면 예시(스크린샷) | 세로형 636×1048 PNG | 3장 (실제 화면) | 전체 (**콘솔상 선택**, 권장) | Playwright viewport 318×524 + deviceScaleFactor 2 (@2x = 636×1048) 캡처. 비주얼 QA 페이즈 스크린샷 재활용 |
| 앱 썸네일(배너) | 1932×828 PNG | 1장 | **게임 앱** | HTML/CSS 컴포지션(브랜드 배경 + (선택적) 텍스트 + 심볼/그래픽, **스크린샷·폰 목업 금지**) → 렌더 |

- 콘솔은 화면 예시로 **세로형 636×1048(최소 3장)** 또는 **가로형 1504×741(최소 1장)**만 허용한다. 본 파이프라인은 세로형 636×1048 3장으로 고정한다. 제출 자체는 선택이지만, 제출한 미니앱부터 순서대로 미니앱 홈에 노출되므로 **항상 제출한다**.
- **썸네일은 공홈 기준 게임 앱 항목**이다. 비게임 앱은 로고 + 스크린샷이 노출 에셋이다. 비게임에서 썸네일을 만들더라도 콘솔 필수 항목은 아니다.

### 앱 로고 필수 요건 (공홈, 위반 시 반려)

- 정사각형 **600×600px PNG**
- **모서리가 둥근 형태 불가** — 각진 정사각형으로 만든다
- **배경색 필수** — 투명 배경 불가. 라이트·다크 모드 모두에서 잘 보이는 배경을 쓴다
- 로고 자체에 배경이 포함된 이미지라면 600×600 영역에 꽉 차게 배치한다
- 작은 화면에서도 선명하고, 서비스 특성이 드러나며, 다른 앱과 혼동되지 않아야 한다
- **토스가 제공하는 아이콘·이모지·이미지 리소스는 로고·썸네일에 쓸 수 없다(2차 가공 포함)** — 서비스 화면 내 UI 용도로만 허용된다
- 저작권 문제가 없어야 한다

### 썸네일 유의사항 (공홈)

- 핵심 플레이 화면이나 주요 기능이 보이는 이미지를 쓴다
- 규격에 맞춰 만들고 **빈 공간을 색·블러로 채우지 않는다**
- 작은 이미지를 늘려 쓰지 않는다(고화질)
- 텍스트는 최소화하고, 로고를 쓴다면 서비스명이 명확히 보여야 한다
- 비속어·정치적 표현 등 편견이 담긴 요소를 넣지 않는다

## 2. 산출 경로

모든 에셋은 프로젝트의 `docs/assets/` 디렉토리에 저장한다.

- `docs/assets/icon.png` — 앱 아이콘 (600×600)
- `docs/assets/screenshot-1.png` ~ `docs/assets/screenshot-3.png` — 앱 화면 예시 (각 636×1048)
- `docs/assets/thumbnail.png` — 앱 썸네일 (1932×828)

콘솔 업로드 관련 산출물은 별도 파일이 아니라 `docs/SUBMIT.md`의 '제출 에셋' 섹션에 집약해 기록한다.

## 3. 디자인 원칙

- **brand primaryColor 활용**: 앱의 `apps-in-toss.config.ts`에 정의된 `brand.primaryColor`를 배경/강조색으로 사용한다 (SDK 2.x 프로젝트는 `granite.config.ts`).
- **TDS 톤앤매너**: 토스 디자인 시스템(TDS)의 톤앤매너를 따른다. 과한 장식 금지, 여백과 위계 중심.
- **텍스트는 선택**: 썸네일 텍스트는 필요할 때만 넣는다 — 비주얼만으로 충분하면 텍스트 없이 만든다. 넣는다면 짧게(키워드 1개~한 줄), 배경과 충분한 대비를 확보한다.
- **썸네일은 창의적 브랜드 표현**: 배너에 스크린샷·폰 목업을 넣지 않는다 (화면 캡처는 '화면 예시'가 담당). 단순 그라데이션+중앙 텍스트는 금지 — 비대칭 레이아웃·추상 도형·떠다니는 칩·큰 타이포·깊이감 중 2가지 이상으로 시선을 끈다 (`references/thumbnail-composition.md` 창의성 원칙).
- **아이콘 모티프 채움**: 배경을 제외한 **실제 렌더된 모티프의 바운딩박스**가 600 캔버스의 78% 이상(한 변 468px+)을 차지해야 한다(컨테이너 박스가 아니라 그려진 픽셀 기준). 캡처 후 비배경 픽셀 바운딩박스를 실측 검증하고, 미달이면 키워 재렌더(`references/icon-template.md` fill-ratio 검증).
- **아이콘은 단순 심볼 + 배경**: 복잡한 일러스트 대신 단순 심볼과 단색/그라데이션 배경으로 구성한다.

## 4. 에셋 정체성 규칙 (앱별 차별화 필수)

모든 앱의 에셋이 비슷한 템플릿 룩으로 수렴하는 것을 금지하는 상위 규칙. 기존 창의성 가이드(그라데이션·다중 레이어·비대칭 레이아웃)는 "무엇을 다르게"의 규칙이고, 본 절은 "앱마다 다르게"를 강제한다.

- **에셋 컨셉 선언 선행**: 아이콘·썸네일 생성 전에 앱의 DESIGN.md에서 ① 주조색 팔레트(앱 도메인·무드에서 도출, 앱마다 달라야 함) ② 핵심 기능 메타포(아이콘 심볼의 소재 — 예: 가계부=동전/장부, 러닝=신발/경로) ③ 무드 키워드 2개를 추출해 2~3줄 "에셋 컨셉 선언"을 먼저 기록한다. 모든 에셋은 이 선언을 따른다.
- **토스블루 기본 사용 금지**: 토스블루(#3182f6)는 앱의 brand 실제색일 때만 사용한다. 그 외에는 앱 도메인·무드에서 주조색을 새로 도출한다.
- **텍스트는 필요할 때만**: 썸네일 텍스트가 불필요하면 비주얼-only로 만든다. 카피 강제 금지.
- **아키타입 차별화**: 썸네일 컴포지션 아키타입(`references/thumbnail-composition.md` 4종)을 최근 앱과 다르게 고른다.
- **템플릿 룩 금지**: 직전 앱(또는 예시 템플릿)과 동일한 팔레트·그라데이션 방향·레이아웃 구도를 그대로 재사용 금지. 렌더 템플릿(`references/`)은 구조(규격·여백) 참고용일 뿐, 색·모티프·구도는 앱마다 새로 결정한다.
- **기능 반영**: 아이콘 심볼은 앱의 핵심 기능을 표현하는 고유 메타포여야 하며, 일반 추상 도형(원·사각 단독)만으로 구성 금지. 썸네일(배너)의 카피·도형 모티프도 앱 기능에서 도출한다.
- **자가 점검**: 생성 후 다음 2문항 자가 점검을 기록한다 — ① 이 에셋만 보고 앱의 기능을 추측할 수 있는가? ② 직전 앱 에셋과 나란히 놓으면 다른 앱으로 보이는가?

## 5. 생성 절차

1. **아이콘 HTML/SVG 작성** — `references/icon-template.md`를 참조해 600×600 아이콘 마크업을 만든다.
2. **Playwright로 각 규격 렌더·캡처** — `references/playwright-capture.md`의 표준 스니펫으로 아이콘·화면 예시·썸네일을 캡처한다.
3. **sips로 실측 검증** — 각 PNG의 실제 픽셀 크기를 확인한다.
   ```bash
   sips -g pixelWidth -g pixelHeight docs/assets/icon.png
   sips -g pixelWidth -g pixelHeight docs/assets/screenshot-1.png
   sips -g pixelWidth -g pixelHeight docs/assets/thumbnail.png
   ```
4. **불일치 시 재렌더** — 규격과 다르면 viewport·deviceScaleFactor를 점검하고 재렌더한다.

## 7. 규격 불확실 시

번들 문서가 stale일 수 있다. 규격이 불확실하면 공홈 조회(https://developers-apps-in-toss.toss.im/)를 우선하라. 콘솔 UI가 요구하는 픽셀 수치가 본 문서와 다르면 공홈/콘솔 표기를 따르되, 변경 사항을 본 스킬에 반영한다.
