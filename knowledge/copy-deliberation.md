# 클릭 유도 문구 다중 에이전트 의논 절차

## 1. 적용 대상

다음 영역의 클릭 유도 문구를 작성·검토할 때 이 절차를 따른다.

- 스마트발송 메시지 (캠페인 제목·메시지 제목·메시지 내용)
- 알림동의문 문안
- 푸시 알림 카피
- 코치마크 카피 (Tooltip·BottomSheet CTA 등)
- 프로모션·리워드 카피 (참여 유도 문구·CTA 버튼 레이블 등)

## 2. 3관점 에이전트

의논은 아래 3관점을 1라운드 고정으로 수행한다. 추가 관점 도입·2라운드 이상의 순환 토론은 금지한다.

| 관점 | 역할 | 핵심 판단 기준 |
|------|------|----------------|
| (가) 카피라이터 | 후킹·CTA·글자수 최적화 | 제목 7자·본문 25자 이내, CTA 명확성, 문장형 "~요." 마침표, 클릭 동기 유발 |
| (나) 타겟 유저 공감 | 토스 유저 관점 공감·거부감 진단 | `knowledge/toss-user-insights.md` 기반 — 핵심 활성층(40대↑) 공감, 20대 이탈 방지, 실생활 연관성 |
| (다) 규정·금지표현 검수 | 검수 거절 사유 사전 차단 | `skills/ait-smart-message/SKILL.md` L41-102 작성규칙·금지표현 기준 — 과장·불안 조성·은어·느낌표·이모지·띄어쓰기 생략 여부 |

## 3. 절차 (1라운드 고정)

```
Step 1 — 후보안 제시
  각 관점이 독립적으로 후보 문구를 1~2개씩 제시한다.
  (가) 카피라이터: 후킹·글자수 최적화 안
  (나) 타겟 유저 공감: 공감 가능성·거부감 진단 포함 안
  (다) 규정·금지표현 검수: 규정 통과 가능성 기준 안

Step 2 — 상호 비평
  각 관점이 다른 두 관점의 후보안에 대해 수용·우려 의견을 1줄씩 제시한다.
  비평 대상: 글자수 위반, 금지표현 포함, 타겟 이탈 리스크 등

Step 3 — 합의
  3관점 비평 결과를 반영해 합의안 1개 + 차순위 1개를 확정한다.
  합의 불가 시 (다) 규정·금지표현 검수 관점이 부적합 판정한 안은 탈락 처리한다.
```

## 4. 출력 포맷

의논 완료 후 아래 형식으로 출력한다.

```
### 클릭 유도 문구 의논 결과

**최종 문구 (합의안)**
- 제목: {문구}
- 본문: {문구}

**A안 (합의안)**
- 제목: {문구}
- 본문: {문구}

**B안 (차순위)**
- 제목: {문구}
- 본문: {문구}

**선정 근거**
- (가) 카피라이터 관점: {후킹·CTA·글자수 평가}
- (나) 타겟 유저 공감 관점: {공감도·거부감 평가}
- (다) 규정·금지표현 검수 관점: {검수 통과 여부}

**금지표현 검수 통과 여부**
- [ ] 은어·밈 없음
- [ ] 과장된 광고성 표현 없음 ("지금 바로!", "초특가!", "역대급" 등)
- [ ] 불안감 조성 없음 ("지금 안 하면 손해" 등)
- [ ] 느낌표·이모지 없음
- [ ] 글자수 준수 (제목 7자 이내, 본문 25자 이내)
- [ ] 마침표 형식 준수 ("~요." 문장형)
```

## 5. 오케스트레이터 디스패치 가이드

새 에이전트 타입을 정의하지 않는다. 기존 에이전트를 3관점으로 역할 지정하여 의논시킨다.

### 단일 에이전트 순차 수행 (기본)

오케스트레이터(planner 또는 executor)가 하나의 에이전트에 3관점을 순서대로 수행하도록 지시한다.

```
프롬프트 패턴:
"아래 문구를 3관점으로 검토하라.
(가) 카피라이터 관점: 후킹·CTA·글자수 최적화 후보안 제시
(나) 타겟 유저 공감 관점(knowledge/toss-user-insights.md 기반): 공감도·거부감 진단 후보안 제시
(다) 규정·금지표현 검수 관점(ait-smart-message/SKILL.md L41-102 기준): 검수 통과 후보안 제시
각 관점 제시 후 상호 비평 → 합의안 1개 + 차순위 1개 + 선정 근거 출력.
출력은 copy-deliberation.md §4 포맷을 따른다."
```

### 병렬 에이전트 수행 (agmo:parallel 사용 시)

3개 에이전트를 동시 디스패치하고 결과를 취합한다.

- **에이전트 1** (designer 또는 executor): (가) 카피라이터 관점 후보안
- **에이전트 2** (explorer 또는 architect): (나) 타겟 유저 공감 관점 후보안 (`knowledge/toss-user-insights.md` 참조)
- **에이전트 3** (critic 또는 quality-reviewer): (다) 규정·금지표현 검수 관점 후보안 (`skills/ait-smart-message/SKILL.md` L41-102 참조)

취합 후 오케스트레이터가 Step 2(상호 비평)·Step 3(합의)를 수행하고 §4 포맷으로 출력한다.

### 주의사항

- 1라운드 초과 순환 금지 — Step 1·2·3 각 1회로 종료한다.
- (다) 규정·금지표현 검수 관점이 부적합 판정한 안은 최종 합의안 후보에서 제외한다.
- 각 SKILL의 기존 작성 규칙·금지표현은 이 파일로 이전하지 않는다 — 원본 SKILL.md를 참조한다.
