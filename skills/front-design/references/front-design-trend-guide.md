# 트렌드 가이드 — TDS 제약 내 차별화 기법

TDS-only 제약(커스텀 컴포넌트 금지) 안에서 화면을 "트렌디"하게 만드는 기법 카탈로그다. 토스 앱의 실제 패턴을 기반으로 한다. 커스텀 컴포넌트로 차별화하려 하지 말고, TDS 컴포넌트의 **조합·위계·카피**로 개성을 만든다.

## TDS 최다 사용 핵심 11컴포넌트(공식)

공식 문서 기준 TDS에서 가장 많이 사용되는 핵심 컴포넌트 11종: `Badge`, `Border`, `BottomCTA`, `Button`, `Asset`, `ListRow`, `ListHeader`, `Navigation`, `Paragraph`, `Tab`, `Top`. 화면을 구성할 때 이 11종을 우선 사용하는 것을 권장한다. 같은 역할을 할 수 있다면 이 핵심 컴포넌트로 먼저 해결하고, 그 외 컴포넌트는 필요할 때 보조적으로 쓴다.

## 큰 숫자 강조

핵심 지표를 Top 영역에 `t1`~`t2` 타이포로 크게 노출하고, 보조 정보는 `t6`~`t7`로 대비시킨다. 한 화면에 "주인공 숫자" 하나를 두면 첫인상의 기억점이 생긴다. 모든 텍스트를 같은 크기로 나열하지 않는다.

## 감정 있는 빈 상태

`Result` 컴포넌트 + 상황 맞춤 이모지/일러스트 + 위트 카피 + 행동 유도 버튼으로 구성한다.

- 좋은 예: "아직 텅 비었어요. 첫 기록을 남겨볼까요?"
- 나쁜 예: "데이터가 없습니다."

빈 상태는 사용자가 가장 먼저 마주치는 화면일 수 있으므로, 감정과 다음 행동을 함께 준다.

## 컬러 의미 체계

컬러를 의미 단위로 일관 운용한다.

- 수입 = green/blue
- 지출 = red
- 중립 = grey

`Badge`·`Paragraph`의 color 토큰으로 위계를 만든다. 의미 없이 다른 컬러를 섞지 않는다.

## 리스트 리듬

`ListHeader`로 그룹핑하고, `ListRow`의 `AssetIcon`(이모지를 원형 배경에 담은 형태)으로 시각 리듬을 만든다. 동일 높이의 ListRow만 끝없이 나열하면 단조롭다. 헤더와 아이콘으로 호흡을 준다.

## 마이크로 카피

토스트·다이얼로그·버튼 레이블의 문구를 디자인 컨셉의 보이스에 맞춰 일관시킨다.

- 발랄/위트 보이스: "저장됐어요"
- 단정 보이스: "저장되었습니다"

한 앱 안에서 보이스가 섞이지 않게 한다.

## 표현 컴포넌트 적극 사용

`BarChart`·`Badge`·`SegmentedControl`·`Tooltip`(코치마크)을 적극 사용한다. 데이터를 텍스트로 나열하는 대신 시각 표현으로 보여준다.

## 안티패턴

- 전 화면 `ListRow` 나열 (리듬·위계 없음)
- 기본 문구 빈 상태 ("데이터가 없습니다" 류)
- 액센트 컬러 없는 무채색 화면
- 의미 없는 다른 컬러 혼용
