# 검수 체크리스트

> 21개 앱 실제 반려 사례 기반. 출시 전 아래 11단계를 순서대로 실행한다.

## 1단계: apps-in-toss.config.ts 검증 (SDK 3.x)

> SDK 2.x 프로젝트는 파일명이 `granite.config.ts`이고 필드 구성이 다르다. **신규 프로젝트는 3.x 기준으로 점검하고**, 2.x면 먼저 `npx ait migrate v3`로 올린다.

- [ ] 파일명이 `apps-in-toss.config.ts` (2.x `granite.config.ts`가 남아 있으면 마이그레이션 미완)
- [ ] `appName` 설정됨 — 케밥-케이스, **콘솔에 등록한 appName과 완전 일치**(등록 후 변경 불가)
- [ ] `brand.primaryColor` 설정됨 (예: `'#3182F6'`)
- [ ] `permissions` 배열 존재 (빈 배열이라도 필수)
- [ ] `defineConfig` import가 `@apps-in-toss/web-framework/config`에서 옴
- [ ] (선택 필드를 쓴다면) `navigationBar`·`webView`·`webBundleDir` 스키마가 3.x 타입과 일치
- [ ] **2.x 잔재 없음** — `brand.displayName`·`brand.icon`·`webViewProps`·`web`·`outdir`은 3.x에 존재하지 않는 필드다
- [ ] `package.json`의 `build` 스크립트에 `vite build`와 `ait build`가 **모두** 포함됨 (`ait build` 단독은 stale dist를 포장)
- [ ] 재빌드라면 `package.json` version이 직전 업로드보다 높음

## 7단계: 광고 정책 (**광고를 도입하는 경우에만 적용**)

> **광고 도입은 공홈 정책상 필수가 아니다.** 공홈(app-nongame·monetization/in-app-ad)의 광고 서술은 전부 "광고를 넣는 경우"의 조건부 규칙이며, 광고를 넣으라는 의무 규정은 없다. 광고 미포함 앱은 7단계 전체를 **N/A**로 처리한다 — 광고가 없다는 이유로 반려되지 않는다.
>
> **프로젝트 컨벤션 (공홈 미검증)**: 이 플러그인은 수익화를 위해 최소 배너 1개 포함을 **권장**한다(사용자 지시 2026-06-11 "광고·푸시·프로모션 적극 추천"). 어디까지나 권장이며 검수 기준이 아니다. 구독·인앱결제 등 다른 수익 모델을 택했다면 광고 미포함으로 확정하고 그 근거를 `PLAN.md` 수익 모델 절에 기록한다.

- [ ] `isSupported()` 체크 후 광고 API 호출
- [ ] cleanup 함수 호출하여 리소스 정리
- [ ] "광고" 표기 제거/변조하지 않음
- [ ] SDK 기본 클릭/노출 로직 수정하지 않음
- [ ] 자동 클릭/자동 새로고침 등 비정상 트래픽 없음
- [ ] 광고 색상, 배치, 크기 임의 변경하지 않음
- [ ] 클릭 시 리워드 제공 문구 추가하지 않음

## 반려 시 대응

반려 사유는 보통 위 11단계 중 하나에 해당한다. 콘솔에서 '반려 사유 보기'로 사유를 확인하고, 문제를 고친 새 번들을 업로드해 다시 검토를 요청한다. 사유가 모호하면 채널톡으로 문의할 수 있다.

**검토 절차·기간 (공홈)**
- 앱 정보 검토: 영업일 **1~2일**. 이게 끝나야 출시할 수 있다.
- 앱 번들(출시) 검토: 영업일 **최대 3일**, 카테고리에 따라 **7일 이상** 걸릴 수 있다.
- 검토 요청은 **한 번에 한 버전만** 가능하고, 테스트를 1회 이상 완료해야 버튼이 활성화된다.
- 제출 후 버그를 발견하면 **'요청 취소하기'**로 회수한 뒤 수정 번들을 다시 올린다.
- 승인되면 콘솔 '출시하기'를 눌러야 공개된다. 출시는 전체 사용자에게 즉시 반영되고, 미니앱 리스트에는 약 1시간 후 노출된다.
- 문제가 생기면 '앱 출시' 메뉴에서 이전 버전을 선택해 **롤백**할 수 있다. 단 **SDK 3.x로 출시한 뒤에는 2.x 번들로 롤백할 수 없다**.
- 출시 후에도 **사후 검수**가 진행된다. 법·정책 위반이 확인되면 긴급 운영 중단이 먼저 적용될 수 있다.

## 최신 반려 사례·정책 (공홈 보강)

- **콘텐츠 제한 8종 (출시 불가)**: 디지털/가상자산(NFT 포함), 자금세탁 위험(현금·자산 직접 교환·전환·환불), 불법 행위 조장, 사행성, 금융상품 중개·판매·광고, 투자 자문, 의료(원격진료/예약/광고비 수취), 기타 내부 정책 위반
- **확인 필요 카테고리**: 의료(공공데이터 기반 정보 조회만), 쇼핑몰(고객센터·환불정책 필수), 교육(국가 전문자격증 필수)
- **생성형 AI**: AI 활용 사실 사전 고지 + 결과물에 명확한 표시(배지·워터마크). 위반 시 최대 3,000만원 과태료
- **어뷰징**: 동일 워크스페이스 유사 핵심 기능 앱 중복 출시 금지, 동일 브랜드로 여러 미니앱 출시 금지(목적·기능이 명확히 다르면 가능). 위반 시 수정 요청 → 미노출 → 등록·운영 제한
- **자사 앱 설치/외부 링크**: 모든 설치 권유·강요 금지, 결제창·다운로드 페이지 이동 금지(법률 고지·공공기관 연결만 허용)
- **다크패턴**: 고객 예상을 벗어난 설계의 미니앱은 출시 불가
- **인트로 페이지 부재 (실사례 반려)**: "서비스 설명 없이 즉시 토스 로그인을 유도하고 있어 인트로 페이지 추가가 필요해요. 서비스를 소개하는 인트로 페이지가 먼저 노출된 후 토스 로그인이 진행될 수 있도록 수정해 주세요." — 진입 즉시 `appLogin()` 호출이 원인
- **고정형 탭바 (실사례 반려)**: "탭바를 사용하는 경우, 토스 미니앱 브랜딩 가이드에 적합한 플로팅 형태를 사용해야 해요." — 하단 고정 바가 원인. 좌우 여백·알약 라운드·그림자의 플로팅 형태로 직접 재구현해야 통과(TDS에 해당 컴포넌트 없음)
