# 푸시 알림 마케팅 소재 가이드

> **사용자 직접 수행 영역과 적극 추천 의무**: 알림동의문 등록·캠페인 생성 등 푸시알림 설정은 사용자가 콘솔에서 직접 수행한다 — 콘솔 설정을 자동화하지 않는다. 에이전트는 **세그먼트·캠페인·문구 설계를 적극 추천·산출**하고(create/update 시 APP-SPEC.md 세그먼트 설계·스마트발송 캠페인 설계 섹션 필수), 콘솔 등록·발송 수행만 사용자가 직접 한다. 단 `ait-console test-send`(배포 후 테스트 푸시)는 설정이 아닌 배포 검증 단계로 자동 수행 대상이다. (사용자 지시 2026-06-11)

## 광고성 vs 기능성 구분

스마트발송은 **광고성 메시지 전용**이다 — 기능성은 별도 콘솔 발송(아래 절 참조).

| 구분 | 목적 | 예시 | 검수 | 발송 경로 | 제한 |
|------|------|------|------|-----------|------|
| 광고성 | 마케팅·프로모션 | 할인 이벤트, 신규 상품 홍보, 캠페인 프로모션 | 스마트발송 검수(최대 3영업일) | 스마트발송(콘솔) | 마케팅 수신 동의 사용자만 |
| 기능성 | 서비스 필수·사용자 선택 알림 | 결제 완료, 배송 현황, 재입고 알림, 이벤트 시작 알림 | 소재 검토 승인 | 콘솔 직접 발송(서버 불필요) | 사전 알림 동의 등록(콘솔 기능) 선행 필요 |

기능성(서비스 필수 정보) 알림은 스마트발송으로 발송할 수 없다.

## 기능성 메시지 (콘솔 발송)

2026-05-28 변경 사항: 기존에는 서버 연동을 통해서만 기능성 메시지를 발송할 수 있었으나, 이제 콘솔에서 직접 발송 가능하다. (출처: https://toss.im/apps-in-toss/blog/update-26-5-28)

### 선행 조건 — 알림 동의 등록

기능성 메시지 발송 전에 **알림 동의 등록(콘솔 기능)** 이 완료되어 있어야 한다.

- 콘솔 경로: 워크스페이스 → 미니앱 → 스마트 발송 → **알림동의문** 탭
- 코드 연동 함수: `requestNotificationAgreement`
- 결제 완료·배송 시작 등 거래 필수 정보는 동의문 불필요. 재입고 알림·이벤트 알림 등 사용자가 명시적으로 신청한 선택적 알림은 동의문 필요.

### 발송 방법

- 콘솔에서 "토스에게 발송 요청하기" 기능으로 직접 발송 (서버 개발·토스 로그인 연동 불필요)
- 콘솔 경로: 워크스페이스 → 미니앱 → 스마트 발송 → 캠페인 생성
- 메시지 제목·내용·이동 URL 작성 → 소재 검토 승인 후 활성화
- 일회성 또는 정기 발송 선택 가능
- **콘솔 발송 자동화**: `ait-console test-send`로 테스트 버전 발송을 자동 수행할 수 있다. 기능성 템플릿 심사 대기는 `ait-console template-watch`가 심사 통과를 자동 감시하고 완료 시 알림을 제공한다.

## 메시지 작성 규칙 (공식)

### 캠페인 구성 요소

| 항목 | 규칙 |
|------|------|
| 캠페인 제목 | **7자 이내(공백 포함), 목적이 드러나는 제목** |
| 캠페인 그룹 이름 | 발송 목적·실험 의도를 표현 |
| 메시지 제목(광고성) | **7자 이내(공백 포함), ~하기/명사형** |
| 메시지 제목(기능성) | **7자 이내(공백 포함), 명사형** |
| 메시지 내용 | **25자 이내(공백 포함), 문장형 "~요." + 마침표 필수** |
| 비게임 앱 | **"토스에서" 미포함** — 공홈 가이드는 포함을 권장하나 사용자 지시(2026-06-12)로 쓰지 않는다 |
| 게임 앱 | 메시지에 **"게임"** 단어 명시 (파생 장르명·전문용어 금지 — "퍼즐 게임", "액션 게임" 등 직관적 장르명 사용) |
| 변수 처리 | 변수는 **2글자로 간주** |
| 제목-본문 연결 | 제목은 그 자체로 완성된 단어/문장, 제목-본문이 자연스럽게 연결되어야 함 |
| 타겟 | 마케팅 수신 동의 사용자 + 세그먼트로만 발송 |
| 캠페인 중복 금지 | 동일 마케팅 목적으로 다중 캠페인 생성 금지 (어뷰징 간주) |
| 발송 한도 | 워크스페이스당 10만 건 |

| 본문 | "토스 할인 혜택 확인하세요" | 마침표 없음, "~요." 형식 미준수 |

### 금지 표현

다음 표현이 포함된 문구는 검수 거절 사유가 된다:

- **은어·밈**: 유행어, 인터넷 신조어
- **특정인 이름**: 연예인·유명인 등 실명 언급
- **과장된 광고성 표현**: "지금 바로!", "초특가!", "역대급", "긴급!", "대박", "무조건", "100%" 등
- **불안감 조성**: "지금 안 하면 손해", "마지막 기회", "놓치면 후회" 등
- **느낌표·이모지**: 모든 형태 금지
- **띄어쓰기 생략**: 글자수 맞추려 붙여 쓰는 행위
- **어색한 조사 생략**: 자연스러운 문장이 되어야 함

## CTR 최적화 — AI 자동 최적화

AI(Machine Learning)가 **pCTR(예측 클릭률) 기반**으로 고관여 사용자를 예측하고, 클릭이 잘 되는 발송 시간을 자동으로 최적화한다. 발송 시점과 타겟 선정은 AI 자동 최적화가 기본이다.

## 발송 메커니즘

### 발송 흐름

스마트발송은 **테스트 발송 → 본 발송** 순으로 진행된다.

### 활성화 시간대별 자동 일정

| 활성화 시각 | 테스트 발송 | 본 발송 |
|-------------|------------|---------|
| 00:00 ~ 04:59 | 당일 08:00 | 당일 15:00 |
| 05:00 ~ 11:59 | 당일 15:00 | 다음날 08:00 |

### 발송 기간 설정 기준

- 검수 최대 **3영업일** + 테스트 발송 최대 **7일**을 고려해 발송 기간을 설정한다.
- 발송 기간이 짧으면 검수·테스트 완료 전 기간이 만료될 수 있으니 여유 있게 설정한다.

### 어뷰징 주의

동일한 마케팅 목적으로 여러 캠페인을 생성하면 **어뷰징으로 간주**된다. 하나의 목적에는 하나의 캠페인을 사용한다.

## 세그먼트 타겟팅

출처: https://developers-apps-in-toss.toss.im/segment/intro.html

스마트발송 타겟은 마케팅 수신 동의 사용자 중 **세그먼트**로만 선택한다. 세그먼트는 콘솔에서 조건 기반으로 유저 그룹을 생성한다. 콘솔 등록은 사용자 직접 수행.

토스는 실제 결제 데이터 기반 100+개 카테고리로 무료 타겟팅 가능.

### 조건 카테고리 4종

| 카테고리 | 포함 항목 |
|---------|---------|
| 거래 정보 | 브랜드·광고 카테고리·토스페이 사용 여부 |
| 유저 정보 | 나이·성별·신용점수·앱 버전·통신사·지역 |
| 유저 활동 | 앱 내 행동 이력 (미니앱 접속 기준) |
| 유저 프로파일 | 금융 성향·라이프사이클·관심사 추정 |

- 여러 조건은 **AND/OR 조합** 가능
- **예측형 세그먼트**: 정확도 설정 필수 — 일반적으로 **50% 이상 권장** (정확도↑ = 모수↓)
- 세그먼트명은 **삭제 후 재사용 불가** — 신중히 명명
- **즐겨찾기 설정** 시 푸시·알림·스마트발송에서 바로 사용 가능

### APP-SPEC 세그먼트 설계 연계

create/update 시 **APP-SPEC.md 세그먼트 설계 섹션(3개 이상)** 을 필수 작성한다. 스마트발송 캠페인 설계에서 이 세그먼트를 타겟으로 지정한다.

### 주요 세그먼트 활용

| 세그먼트 | 타겟팅 키워드 예시 | 적합한 앱 |
|---------|-----------------|---------|
| 커피 소비자 | "커피 자주 마시는" | 카페 추천, 쿠폰 |
| 1인가구 | "혼자 사는" | 생활 팁, 요리 |
| 뷰티/패션 | "뷰티 트렌드 관심" | 뷰티 퀴즈, 추천 |
| 투자 관심 | "금융 정보 관심" | 계산기, 세금 |
| 게임 이용자 | "게임 자주 하는" | 미니게임, 퀴즈 |

### 토스 유저 특성

- **핵심 활성층: 40대 이상** — 20대 CTR 매우 낮음
- 10대는 앱인토스 사용 불가

## 랜딩 URL

- 랜딩 URL은 정상 접속 가능한지 반드시 확인한다.
- **하나의 캠페인에서 소재별로 다른 랜딩 URL을 설정할 수 없다.** 캠페인 내 모든 소재는 동일한 랜딩 URL을 사용해야 한다.

## A/B 테스트 (보조 참고)

AI 자동 최적화가 기본이지만, 수동으로 문구 변수를 비교하는 A/B 테스트를 병행할 수 있다. 단, 발송 시간 설정은 AI 자동 최적화와 중복되므로 문구 변수 위주로 테스트한다.

### 테스트 변수 예시

| 변수 | A안 | B안 |
|------|-----|-----|
| 문구 스타일 | 정보형 "이번 주 소식" | 호기심형 "이거 받으셨나요?" |
| 이모지 | 없음 | 있음 |
| 수치 포함 | 없음 | "3개 남았어요." |

### 대조군 설정

- 변수 하나만 변경 (문구만)
- 최소 1일 이상 실행
