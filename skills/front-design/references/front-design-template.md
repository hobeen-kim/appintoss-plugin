# GLOBAL.md 템플릿

앱 전체에 적용되는 디자인 가이드. 페이지별 DESIGN.md 작성 전에 먼저 확정한다.

```markdown
# {앱 이름} 디자인 가이드

## 앱 테마
- **톤앤매너**: {밝고 경쾌한 / 차분하고 신뢰감 있는 / ...}
- **모드**: 라이트 모드 전용 (앱인토스 규칙)

## 색상 팔레트

### 주요 색상
| 용도 | 색상명 | HEX | 사용처 |
|------|-------|-----|--------|
| Primary | {이름} | {#XXXXXX} | CTA 버튼, 강조 텍스트 |
| Secondary | {이름} | {#XXXXXX} | 보조 버튼, 배지 |
| Background | - | {#XXXXXX} | 페이지 배경 |
| Surface | - | {#XXXXXX} | 카드/섹션 배경 |

### 카테고리/태그 색상 (해당 시)
| 카테고리 | 배경색 | 텍스트색 |
|---------|--------|---------|
| {카테고리1} | {#XXXXXX} | {#XXXXXX} |

### 텍스트 색상
| 용도 | HEX | 사용처 |
|------|-----|--------|
| 기본 텍스트 | #191F28 | 제목, 본문 |
| 보조 텍스트 | #8B95A1 | 설명, 캡션 |
| 비활성 | #D1D6DB | 비활성 요소 |

## 공통 스타일

### 카드
- **배경**: {색상}
- **border-radius**: {값}
- **padding**: {값}
- **shadow**: {값 또는 없음}

### 간격
- **섹션 간**: {값}
- **카드 간**: {값}
- **내부 여백**: {값}

## 공통 TDS 컴포넌트 사용 규칙
- 페이지 헤더: `Top` 사용 여부
- 하단 CTA: `FixedBottomCTA` vs 인라인 `Button`
- 리스트: `ListRow` 기본, 그리드 필요 시 `GridList`
- 로딩: `Skeleton` (콘텐츠 영역), `Loader` (전체 페이지)
- 에러: `Result` 컴포넌트
- 광고: 배너 위치 및 스타일
```

# DESIGN.md 템플릿

## 문서 구조

```markdown
# {페이지명}

## 경로
`/{route-path}`

## 화면 구성

### 레이아웃
{전체 레이아웃 설명}

### 영역별 구성

#### {영역 1}
- **TDS 컴포넌트**: `ListRow`, `Paragraph` 등
- **내용**: {표시할 데이터/텍스트}
- **동작**: {클릭 시 이동, 토글 등}

#### {영역 2}
- **TDS 컴포넌트**: `TextField`, `Button` 등
- **내용**: {입력 필드, 버튼 등}
- **동작**: {입력 검증, 제출 등}

## 상태

### 기본 상태
{정상적으로 데이터가 있을 때}

### 로딩 상태
{데이터 로딩 중 - Skeleton, Loader 등}

### 빈 상태
{데이터가 없을 때 - Result 컴포넌트 등}

### 에러 상태
{API 실패 등 - 에러 메시지 표시}

## 인터랙션

### {인터랙션 1}
1. 사용자가 {동작}
2. {결과/화면 변화}
3. {최종 상태}

## API 연동
| 시점 | 엔드포인트 | 설명 |
|------|----------|------|
| 진입 시 | `GET /api/...` | 초기 데이터 로드 |
| 제출 시 | `POST /api/...` | 결과 저장 |

## 사용 TDS 컴포넌트 목록
- `Top` - 페이지 헤더
- `TextField` - 입력 필드
- `FixedBottomCTA` - 하단 CTA 버튼
- ...
```

## 작성 시 주의사항
- TDS 컴포넌트명은 정확한 이름 사용 (front-tds 스킬 참고)
- API 연동 부분은 docs/API.md와 일치해야 함
- 상태별 화면을 빠짐없이 정의 (특히 에러, 빈 상태)
