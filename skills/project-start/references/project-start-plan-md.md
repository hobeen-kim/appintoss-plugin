# plan.md 작성 가이드

## 용도
프로젝트의 기획 의도, 핵심 기능, 화면 구성을 정리한 문서입니다.
CLAUDE.md와 에이전트 구성의 기반이 됩니다.

## 사용자에게 질문할 항목

### 마케팅 퍼스트 (Step 0 — 코드 전에 먼저)
1. **타겟 유저**: 누가 쓸 앱인가? 토스 유저층(40대+ 활성) 고려했는가?
2. **세그먼트**: 토스 결제 데이터 기반 타겟팅 활용 계획
3. **푸시 문구 초안**: 20자 이내, 유저가 탭하고 싶은 한 줄
4. **카테고리 전략**: 앱인토스 카테고리 중 어디에 노출?

### 필수 질문
5. **프로젝트 이름**: 앱 표시 이름과 식별자(appName)
6. **핵심 기능**: 이 앱이 해결하는 문제, 주요 기능 3~5개 (마케팅 메시지에서 역설계)
7. **주요 화면**: 페이지/화면 목록과 각 화면의 역할

### 상황에 따라 질문
8. **외부 데이터/API**: 필요한 외부 API나 데이터 소스
9. **서버 필요 여부**: 백엔드 API가 필요한지, 필요하다면 어떤 기능
10. **참고 앱/디자인**: 비슷한 앱이나 원하는 UI 스타일
11. **기술적 제약사항**: 특수한 요구사항

## 템플릿

```markdown
# {프로젝트명}

## 개요
{한 줄 설명}

## 마케팅 (코드 전에 먼저)
- **타겟 유저**: {누가, 어떤 상황에서}
- **세그먼트**: {토스 결제 데이터 기반 타겟팅 키워드}
- **푸시 문구**: "{20자 이내 한 줄}"
- **카테고리**: {앱인토스 카테고리}

## 핵심 기능
- {기능 1}: {설명}
- {기능 2}: {설명}
- {기능 3}: {설명}

## 화면 구성

### {화면 1}
- 경로: /
- 역할: {설명}
- 주요 요소: {리스트, 버튼, 입력 필드 등}

### {화면 2}
- 경로: /{path}
- 역할: {설명}
- 주요 요소: {설명}

## 데이터/API
- {필요한 데이터 소스 또는 API}

## 기술적 고려사항
- {특수한 요구사항, 제약사항}

## 에이전트 구성

### 필수
- `app-developer` — 프론트엔드 UI 개발
- `reviewer` — 코드 리뷰 및 검수
- `devops` — 빌드, 배포, 인프라

### 추가 선택
- `{에이전트명}` — {역할} (선택 사유: {이유})

### 프로젝트 고유 에이전트
- `{에이전트명}` — {역할} (신규 생성 사유: {이유})
```

## 작성 원칙
- 사용자의 답변을 그대로 옮기지 말고, 구조화하여 정리
- 모호한 부분은 추가 질문으로 명확히
- 기술적 판단이 필요한 부분은 제안 형태로 작성
- 화면 구성은 라우팅 경로까지 함께 정리
- **에이전트 구성** 섹션은 Step 3 완료 후 추가하며, 선택 사유를 반드시 기록
