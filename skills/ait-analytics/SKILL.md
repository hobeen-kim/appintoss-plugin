# 앱인토스 Analytics 가이드

`@apps-in-toss/web-analytics`를 통해 사용자 행동을 추적합니다.
web-framework에서 re-export되므로 별도 설치 불필요합니다.

## 이벤트 종류
| 메서드 | 용도 | 예시 |
|--------|------|------|
| `screen` | 화면 진입 | 페이지 로드 시 |
| `impression` | 요소 노출 | 배너, 결과 영역이 뷰포트에 보일 때 |
| `click` | 사용자 클릭 | 버튼, 링크 클릭 시 |

## 로그 설계 원칙 (개발 착수 전에 정한다)

**로그는 개발이 끝난 뒤 붙이는 게 아니라, 개발 지시에 포함시키는 항목이다.**

- **유저는 "나 이제 앱을 종료해요"라고 말해주지 않는다.** 이동·클릭·노출을 **직접 정의해 심어야** 지표가 생긴다.
- AI에게 개발을 위임할 때 **"다른 건 몰라도 로그는 반드시 함께 작성하라"** 를 명시한다. 로그 없는 화면은 나중에 이탈 원인을 알 수 없다.
- 로그의 최소 단위: **화면 진입 · 요소 노출 · 버튼 클릭 · 단계 이동**. 퍼널의 각 단계마다 1개 이상.
- 이 로그가 그대로 **퍼널 대시보드**가 되고, 개선 판단의 유일한 근거가 된다.

> 실측: 로그로 최대 이탈 구간을 특정한 뒤 그 지점 하나만 고쳐 **최종 전환 9% → 14%** 를 만든 사례가 있다.
> 상세는 `references/growth-playbook.md` §4 참조.

## 전환 지표 설계

Phase 0 기획 시 **핵심 전환 지표 1개 + 보조 지표 2개**를 아래 절차로 정의한다.

### 정의 절차

1. **핵심 전환 지표 선정**: 미니앱의 핵심 가치를 대표하는 행동 1개를 선정한다(예: 첫 구매 완료, 특정 레벨 도달).
2. **보조 지표 선정**: 이탈 구간 파악 및 핵심 지표 달성 전 단계를 측정할 이벤트 2개를 선정한다.
3. **이벤트 코드 매핑**: 아래 표를 참고하여 각 지표를 기존 이벤트 메서드로 연결한다.

| 지표 유형 | 권장 이벤트 메서드 | 연결 예시 |
|-----------|-------------------|-----------|
| 핵심 전환 지표 | `click` | 구매 버튼 클릭, 신청 완료 버튼 클릭 |
| 보조 지표 (노출) | `impression` | 결과 화면 노출, 상품 목록 노출 |
| 보조 지표 (진입) | `screen` | 결제 화면 진입, 상품 상세 진입 |

### 콘솔 전환 지표 커스텀 (2026-04-29 추가)

앱인토스 콘솔에서 커스텀 이벤트를 전환 지표로 직접 정의할 수 있다.

- **최대 3개** 등록 가능 (핵심 전환 지표 1개 + 보조 지표 최대 2개)
- **핵심 전환 지표** 1개: 노출 최적화·추천에서 기본 신호로 활용됨
- OR 조건으로 이벤트를 조합하거나 파라미터 조건을 설정할 수 있음
- 지표 변경 내용은 **다음 날**부터 반영됨

## 대시보드 지표 활용

> **출시 후 성장 루프 전체**(노출 3계층 · 외부 채널 · 이탈 진단 → 푸시 처방 · 리텐션 · 운영 자동화)는
> `references/growth-playbook.md`에 실측 사례와 함께 정리되어 있다. `/appintoss:improve` 실행 전 함께 읽는다.

앱인토스 Analytics 대시보드의 지표를 `/appintoss:improve` 명령의 입력으로 활용해 개선 사이클을 구동한다.

### 지표별 활용 방법

| 대시보드 지표 | 개선 사이클 활용 |
|---------------|-----------------|
| 유입 경로 분석 | 유입 채널별 전환율 비교 → 저성과 채널 개선 또는 고성과 채널 집중 |
| **연령·성별 분포** | 주 사용층이 모이는 **외부 커뮤니티를 선택**하는 근거로 쓴다(예: 10·20대 비중이 크면 대학생 커뮤니티) |
| **단계별 이탈(퍼널)** | 최대 이탈 구간 1곳을 특정해 **그 지점에만** 처방한다 — 앞뒤 구간을 함께 바꾸면 효과를 분리할 수 없다 |
| 체류시간 (2026-03-18 추가) | 화면별 체류시간 이상치 탐지 → 이탈 원인 UX 개선 |
| 성능 대시보드 | 로딩 지연·오류율 추이 → 기술 부채 우선순위 결정 |

### 개선 사이클 입력 예시

```
/appintoss:improve
- 유입 경로: 검색 유입 클릭률 2.1% (목표 4%)
- 체류시간: 결제 화면 평균 45초 (직전 대비 +20초)
- 성능: 초기 로딩 P95 3.2초
```

지표 수집 기간은 최소 7일 이상 확보 후 `/appintoss:improve`에 입력한다.
