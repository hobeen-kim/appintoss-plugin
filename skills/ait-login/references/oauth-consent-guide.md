# 토스 로그인 동의 항목 추천 가이드 (콘솔 설정값)

토스 로그인을 쓰는 앱은 콘솔 "토스 로그인 > 동의 항목"에서 각 항목을 **필수 동의 / 선택 동의 / 사용 안함** 중 하나로 설정한다. ait-login이 PLAN.md 기능을 보고 **최소 수집 원칙**으로 추천한다.

## 동의 항목 7종 (scope 키)

| 표시명 | scope 키 | 언제 필요 |
|---|---|---|
| 이름 | `user_name` | 인사·개인화 표시. 기본 후보 |
| 이메일 주소 | `user_email` | 이메일 알림·계정 식별 |
| 성별 | `user_gender` | 성별 기반 콘텐츠·통계 |
| 생년월일 | `user_birthday` | 연령 제한·생일 기능·연령대 통계 |
| 내/외국인 정보 | `user_nationality` | 내외국인 분기 서비스 |
| 휴대전화번호 | `user_phone` | SMS·본인확인·연락 |
| 연계정보(CI) | `user_ci` | 동일인 식별·중복가입 방지(고위험, 꼭 필요할 때만) |

## 핵심 사실 (헷갈리기 쉬움 — 먼저 읽어라)

- **이름(`user_name`)은 필수 동의로 강제된다.** (실측 2026-06-09 콘솔: "이름 USER_NAME — 필수 동의", 해제 불가) → **토스 로그인을 쓰면 동의 항목 0개는 불가능**하고 최소 이름은 켜진다. "userKey만 받고 동의 0개" 같은 결론은 **오답**.
- **이름은 암호화 필드** → 로그인을 쓰는 한 **복호화 키 + AAD 발급 + AES-256-GCM(IV+AAD) 복호화 로직이 항상 필요**하다. 받은 이름을 DB에 저장하지 않더라도 **login-me 응답 파싱을 위해 복호화는 반드시 거쳐야 한다**. (즉 "복호화 불필요"는 로그인 쓰는 앱에선 성립 안 함)
- **userKey는 표준 OAuth `sub`이 아니다.** login-me 응답의 **평문 필드**로, "해당 앱에서만 쓰는 사용자 식별 고유값"이다. 동의 항목과 무관하게 로그인하면 항상 제공된다 → 사용자 식별·저장은 userKey로(코드의 `tossUserKey`).
- **login-me 평문/암호화 구분** (공홈 develop.html):
  - **평문**: `userKey`, `scope`, `agreedTerms`, `di`
  - **암호화(AES-256-GCM)**: 이름, 이메일, 휴대전화번호, 생년월일, CI, 성별, 내/외국인
- **콜백 필수 트리거는 별개**: 이름·이메일·성별은 콜백을 요구하지 않는다. **생년월일·내외국인·휴대폰·CI** 중 하나라도 켤 때만 연동 해제 콜백 필수. (이름만 필수인 기본 앱은 콜백 불필요)
- **약관 URL은 별도로 필요하다.** 토스 로그인 등록 시 서비스 이용약관 URL 필수 → `legal-templates.md`로 생성·서버 정적 서빙해 URL 확보.

> 정리: **로그인 쓰는 앱의 최소 구성 = 이름(필수·암호화) → mTLS + 복호화 키 + AAD + 복호화 로직 + 약관 URL.** 콜백은 생년월일/국적/휴대폰/CI 켤 때만 추가.

## 추천 원칙 (최소 수집)

1. **이름(`user_name`)은 필수 강제이므로 항상 켜진다.** 나머지(이메일·성별·생년월일·내외국인·휴대폰·CI)는 기본 "사용 안함", 앱이 실제로 쓰는 것만 켠다 — 과수집은 검수 반려·이탈 사유.
2. **추가 항목의 필수 동의는 그 항목 없이는 앱이 동작 불가할 때만.** 있으면 좋은 정도면 **선택 동의**.
3. **CI(`user_ci`)는 본인확인·중복가입 방지 등 꼭 필요할 때만.** 단순 식별은 `userKey`(항상 제공)로 충분하므로 CI 불필요.
4. **userKey는 동의 항목과 무관하게 항상 제공**된다. 단, 이름이 필수라 **동의 0개는 불가** — 사용자 데이터를 안 써도 이름은 받게 되고 복호화가 필요하다(저장은 안 해도 됨).

## 콜백 필수 자동 판정 ★

콘솔 안내: **"이름·이메일 주소·성별 외 추가 항목을 선택한 경우, 연결 끊기 콜백 정보를 반드시 입력해야 한다."**

→ `user_birthday`·`user_nationality`·`user_phone`·`user_ci` 중 **하나라도 필수/선택으로 켜면 콜백 필수**.
- 콜백 필수 시 산출: **콜백 URL + HTTP 메서드(GET/POST) + Basic Auth 헤더**를 사용자가 콘솔에 등록하도록 안내. 서버는 `/auth/unlink` 류 엔드포인트로 `userKey`+`referrer`(UNLINK/WITHDRAWAL_TERMS/WITHDRAWAL_TOSS) 수신 처리.
- 이름(필수)·이메일·성별만 켜면 콜백 불필요(단 권장). 생년월일·국적·휴대폰·CI 켤 때만 콜백 필수.

## 약관/동의문 (콘솔 등록) — URL 필수

토스 로그인 등록 시 약관/동의문을 **URL 또는 본문**으로 콘솔에 등록해야 한다. **서비스 이용약관은 필수.**

- **서비스 이용약관 (필수)** — 없으면 로그인 등록 불가.
- 개인정보 처리방침 — 개인정보(이름·이메일·휴대폰·CI 등)를 받으면 사실상 필수.
- 마케팅 정보 수신 동의 / 개인정보 선택적 수집·이용 동의 / 전자적 전송매체 광고성 정보 수신 동의 — 푸시 마케팅 등 해당 기능 쓸 때만 선택 등록.

### 약관 생성·호스팅 절차

1. **초안 생성**: `references/legal-templates.md` 골격으로 서비스 이용약관(+개인정보 처리방침) 초안을 `docs/legal/terms.md`·`docs/legal/privacy.md`에 생성한다. 수집 동의 항목을 개인정보 처리방침의 "수집 항목"에 자동 반영.
2. **호스팅(URL 확보)** — 택1:
   - 미니앱 내 정적 라우트(`/terms`, `/privacy`)로 노출 후 그 URL 사용 (정보성 페이지라 정책 허용).
   - 또는 GitHub Pages·Notion 등 외부 공개 URL.
3. **콘솔 등록**: 확보한 URL을 토스 로그인 약관/동의문에 입력.
4. SUBMIT.md "토스 로그인 설정"에 약관 URL(또는 "호스팅 필요" 상태)을 기록.

> **법적 면책**: 자동 생성 약관은 **초안**이다. 실제 서비스 책임·환불·분쟁·관할 등은 운영자가 법적 검토 후 확정해야 한다. 플러그인은 골격만 제공한다.

## 추천 산출 형식 (SUBMIT.md "토스 로그인 설정" 섹션)

로그인 쓰는 앱만 작성. 동의 항목 표 + 콜백 필요 여부 + 근거 1줄.

| 동의 항목 | scope | 설정 | 근거 |
|---|---|---|---|
| 이름 | user_name | 선택 동의 | 홈 인사 표시 |
| 휴대전화번호 | user_phone | 사용 안함 | 미사용 |
| ... | ... | ... | ... |

- 콜백 필수 여부: {필수(생년월일 선택) / 불필요}
- 약관: 서비스 이용약관(필수) {+ 마케팅 동의 (푸시 사용 시)}

---
> 콘솔 동의 항목·약관 구성은 변동될 수 있다. 불확실하면 콘솔/공홈(https://developers-apps-in-toss.toss.im/) 조회.
